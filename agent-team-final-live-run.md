# Final Team Report

Предложить 3 идеи для iPhone, выбрать лучшую и зафиксировать, что реально можно запустить быстро в рамках локальных ограничений, а что требует дополнительной проверки.

## Constraints

- Запрещены платные сервисы.
- Не делаем предположения без проверки.
- Сценарий должен пройти по роли и QA-проверке.
- Итог должен быть обоснован критериями выбора, а не удачными словами.

## Best Idea
Локальный iPhone-ассистент для быстрых действий: Shortcuts + Notes + Reminders + локальный AI-обёрточный слой, который помогает быстро собирать заметки, создавать шаблоны задач, организовывать повседневные процессы без внешних сервисов.

## Why this one
- Реалистичный для запуска в короткий срок.
- Основан на инструментальной экосистеме iPhone, которая уже есть у пользователя.
- Нет зависимости от платных сервисов.
- Легко проверить на уровне prototype и MVP.
- Имеет понятную ценность: экономия времени на рутину и снижение хаоса в задачах.
- Похоже на продукт, который можно пошагово запускать и улучшать, не теряя контроль над рисками.

## 3 Ideas
### 1. Локальный iPhone-ассистент для задач и заметок
Проблема: пользователь теряет контекст между заметками, задачами и быстрыми действиями.
Ценность: быстрые шаблоны, сбор идей, автоматическая маршрутизация в задачи.
Модель запуска: Shortcuts + Reminders + Notes + локальная логика.
Риск: ограничение на встроенные инструменты и необходимость UX-упрощения.

### 2. Быстрый офлайн-бот для personal knowledge capture
Проблема: мысли, идеи и материалы разбросаны по заметкам, чатам и ссылкам.
Ценность: единый локальный рабочий поток для сохранения и структурирования информации.
Модель запуска: локальное хранилище, шаблоны, индексация, поиск по категориям.
Риск: сложность структурирования без нормальной архитектуры.

### 3. Умный набор автоматизаций для повседневных задач
Проблема: повторяемые действия занимают время и ментальную энергию.
Ценность: автоматизировать привычные рутинные действия через Shortcuts и сценарии.
Модель запуска: базовые automation flows, затем расширение под конкретный сценарий.
Риск: пределы автоматизации и необходимость реального пользовательского сценария.

## Blockers
- Нет подтверждённых внешних пользовательских данных.
- Требуется проверка реальных задач и фича-паритета с реальным использованием.
- Для более продвинутой версии потребуется интеграция с внешними данными или AI-инструментами, что выходит за локальные ограничения.
- При выборе более сложной идеи рост рисков резко выше, чем у базового Shortcuts-driven MVP.

## Remaining Checks
- Проверить, какие действия реально повторяются у пользователя чаще всего.
- Сравнить стоимость разработки и время запуска для каждого сценария.
- Проверить, насколько удобно использовать эти сценарии на iPhone в реальной жизни.
- Уточнить, нужен ли локальный AI-помощник или достаточно хорошо построенной системы шаблонов.
- Зафиксировать принципы персональной приватности и локального хранения.
